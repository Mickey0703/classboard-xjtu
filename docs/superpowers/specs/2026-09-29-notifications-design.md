# 班级通知与待办：设计

日期：2026-09-29

## 目标

班委可在西交班务发布重要公告和带截止时间的待办。同学无需登录即可阅读公开内容；属于本班名单的同学用邮箱一次性验证码登录后，可明确确认“已知悉”，并对待办标记“已完成”。班委可看到逐条通知的知悉率、完成率和未确认名单。论坛不加入本阶段；发布通知时不主动群发邮件。

## 方案选择

延续 Cloudflare Pages、Pages Functions 与 D1。身份验证复用 Cloudflare Access，给学生操作接口配置单独的 Access 应用与 Audience Tag，并启用 One-time PIN 邮箱登录。Access 策略只允许班级邮箱名单，应用服务端再用 D1 名单确认身份。班委继续使用原有管理权限。少于 50 位用户符合当前 Access 免费计划定位；免费计划开通时仍可能需要填写付款资料，正式上线前核对条款。

另一种方案是自行发送和验证邮箱验证码；这需要额外邮件服务、限流和防滥用维护。本阶段不采用。旧日程表也不复用为通知，因为通知需要发布状态、收件人快照和逐人确认记录。

## 用户体验

- 底部导航新增“通知”，不增加论坛入口。通知页按置顶、重要程度、发布时间排序，区分“公告”和“待办”，显示标题、正文、发布时间、发布者、截止时间和状态。
- 首页在课程卡片前突出最新的重要通知，并提供直达入口。无通知时呈现清楚的空状态。
- 未登录者可阅读已发布通知。点击确认时引导到邮箱验证码登录，登录后返回通知页；不把页面浏览自动计入“已知悉”。
- 名单内同学对公告点“已知悉”；对待办可点“已知悉”和“已完成”。完成操作也记为已知悉。重复点击不产生重复记录；完成状态可撤销以纠正误操作。每位同学只能修改自己的状态。
- 班委管理页新增“通知”和“成员”两栏。成员维护姓名和邮箱；发布通知时锁定当时的活跃成员为收件人，保证分母稳定。班委可编辑草稿、发布草稿、撤回已发布通知；发布后正文不直接修改，需撤回重发。
- 班委在通知详情中查看收件总数、已知悉数、待办已完成数，以及尚未知悉或尚未完成的成员名单。收件名单与个人状态不进入公开接口。

## 数据与权限

D1 新增 `class_members`、`notifications`、`notification_recipients` 三表。通知含类型（公告/待办）、重要程度（普通/重要/紧急）、标题、正文、截止时间、置顶、状态（草稿/已发布/已撤回）、创建/发布时间及发布者。收件行以 `(notification_id, member_email)` 唯一，存知悉和完成时间。发布动作在同一数据库事务/批次中写入通知状态与收件人快照；没有活跃成员时拒绝发布。

公开 API 只返回已发布通知的可公开字段。成员 API 必须验证 Access 令牌和 D1 名单，只能读取、修改本人的确认状态。管理 API 必须验证班委身份，才能维护通知和名单、查看统计。服务端验证标题/正文长度、截止日期与状态转换。接口使用 `Asia/Shanghai` 时间。邮件地址按小写存储并比较；停用成员不删除历史收件记录。

## 验收

- 班委可新增成员、撰写草稿、发布公告/待办、撤回通知，并看到准确的逐人统计。
- 访客可阅读已发布内容，看不到草稿、成员名单与个人状态；访客与非名单邮箱不能确认。
- 名单内同学经邮箱一次性验证码登录后可知悉/完成，刷新后状态保留；重复提交幂等，撤销完成后统计同步变化。
- 首页和通知页在手机、桌面均可用；重要通知在首页明显展示，通知页空状态、过期状态和登录引导清楚。
- 本地演示数据与真实班级名单明确区分。现有首页、课表、日程及班委课程编辑不回退。

## 上线依赖与边界

正式使用需提供班级成员姓名和邮箱名单，并在 Cloudflare Access 策略配置相同的邮箱集合。当前开发只建立本地功能和部署说明，不创建外部 Access 应用、不发送邮件、不发布网站。若班级人数达到或超过免费计划范围，应重新评估认证成本。
